# TDG Command Center — Mobile App + Natural Language Query
**Plan Date:** June 2, 2026  
**Status:** Draft — awaiting Renee approval before any build

---

## Goal

Give TDG staff and Renee a mobile-friendly interface to:
1. **Ask questions in plain English** about deals, agents, and performance ("How many pending does Laith have?")
2. **See key dashboards** (leaderboard, active deals, lead gen) on a phone without needing a browser
3. **Get instant answers** without logging into the full web app

---

## Proposed Approach — 3 Options

### Option A — Progressive Web App (PWA) + AI Chat tab ⭐ Recommended
Add a mobile-optimized view and a chat tab to the **existing Railway Flask app**. No new app, no new hosting, no new login. Staff access the same URL on their phone — it just looks and works like a native app.

**How the NLQ works:**
- Chat box sends the question to a new `/api/ask` endpoint
- Endpoint uses Claude (via Hermes) to translate the question → SQL query
- Runs the query against the Command Center DB
- Returns a plain English answer

**Pros:**
- Zero extra cost (same Railway app, same DB)
- No app store, no installs — just "Add to Home Screen" on iPhone/Android
- Same login as the web app (TDGAdmin / staff)
- Can be done in 1–2 days

**Cons:**
- Not a "real" native app (no push notifications without extra work)
- Offline mode not available

---

### Option B — Standalone React Native App
Build a separate iOS/Android app using React Native or Expo.

**Pros:**
- True native feel, push notifications possible
- App icon on home screen

**Cons:**
- Requires Apple Developer account ($99/yr) + app store submission
- 2–4 week build + review process
- Separate codebase to maintain
- Much higher complexity

---

### Option C — Telegram / Discord Bot
Add a `/ask` command to the existing Hermes bot channels.

**Pros:**
- Zero build — Jet already has access to the DB
- Works on mobile immediately (Telegram/Discord apps)
- Could answer "how many pending does Laith have" right now

**Cons:**
- Not a "TDG app" — lives inside a third-party chat
- Staff would need Telegram/Discord accounts
- Not brand-appropriate for agent-facing use

---

## Recommended Path: Option A (PWA + NLQ Chat)

### What gets built

#### 1. Mobile-Responsive Shell
- Bottom tab bar (Home / Leaderboard / My Deals / Ask)
- Existing pages get a `?mobile=1` responsive override
- "Add to Home Screen" manifest so it installs like a native app

#### 2. NLQ Chat Tab — `/ask`
A simple chat interface where anyone can type a question:

| Example question | What it returns |
|---|---|
| "How many pending does Laith have?" | "Laith Marroki has 3 pending transactions." |
| "Who closed the most this month?" | "Casey Wagner — 4 closed in June." |
| "What's our YTD GCI?" | "$831,802 closed + $575,866 pending = $1.4M total." |
| "Show me active listings in Rochester" | Table of active listings filtered by location |
| "How many buyer appts did we set this week?" | Lead gen log summary |

**How it works under the hood:**
1. User types question → POST to `/api/ask`
2. Claude receives: question + DB schema summary + last 30 days of data context
3. Claude generates a safe read-only SQL query
4. Query runs against PostgreSQL
5. Claude formats result as a plain English sentence
6. Response shown in chat bubble UI

**Safety:** Only SELECT queries allowed. No writes via NLQ. Agent names from the question are fuzzy-matched to the agents table first.

#### 3. Mobile-First Pages
- **Leaderboard** — card-based, swipeable, no wide table
- **My Deals** — simplified card view of transactions (no 38-column table on mobile)
- **Lead Gen** — summary numbers by agent
